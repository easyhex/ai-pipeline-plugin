## Nice to have

- Pre-merge regex matches substrings: `git merge-base main HEAD` is blocked (empirical, exit 2) whenever any block condition stands; strings inside `echo`/commit messages match too. Word-boundary the pattern (`git (merge|push)\b`, `gh pr create`).
- Ledger cap `tail -c 524288` can split a JSONL record mid-line — the first line of a truncated ledger is unparsable for per-line jq consumers. Truncate on a line boundary (`tail -n`).
- `scripts/pipeline/resolve-plugin-dir.sh` is dead code: nothing calls it; feature.md restates the sort -V snippet inline 4 times (spec item 4 said "defined once"), and the two variants can drift.
- PIPELINE.md hooks table says all hooks "no-op outside an active pipeline run"; UserPromptSubmit actually injects in every pipeline *project* regardless of run state (guard is docs-meta/PIPELINE.md, prompt-context-inject.sh:7). Doc/behavior mismatch (hard rule 1 territory).
- current.json schema drift vs spec item 2: spec says `{slug, f_id, branch, phase, approvals, updated}`; feature.md writes `started` and never mentions `updated`.
- Template `gitignore` doesn't exclude `docs/superpowers/runs/` — a ~1MB ledger, pid files, and precompact snapshots become commit-able churn in every user repo (`git add -A` is in the TDD loop).
- Contributor CLAUDE.md: v0.7.0 bullet inserted above v0.6.0 (versioning list out of order), and the layered-structure list doesn't mention `hooks/`, `scripts/`, or `tests/promptfoo/`. README "three layers" section likewise omits the new auto-loaded hooks component.
