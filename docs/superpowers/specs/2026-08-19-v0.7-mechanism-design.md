# v0.7 «Механизм» — design

**Status:** APPROVED — three open decisions answered by the user on 2026-08-19 (all recommended).
**Sources:** grill report (architecture lens A1–A10), survey (disler/claude-code-hooks-mastery hook contracts, cc-sdd approvals ledger, OpenSpec stateless state, promptfoo behavioral CI), Serena memories (runstate-substitutes-v04, command-bash-block-state, phase-insertion-jump-audit, vacuous-verdict-guard).

## Goal

Enforcement moves from prose into the harness: hooks the model cannot forget, verdicts machines can parse, bash that lives in testable files, run state that survives session death, and a behavioral CI for the plugin itself.

## Decisions (user-confirmed 2026-08-19)

- D1 **Hooks live in the plugin** (`hooks/hooks.json` + `scripts/hooks/*.sh` via `${CLAUDE_PLUGIN_ROOT}`): apply automatically wherever the plugin is enabled; every script carries a no-op guard (not a pipeline project / no active run → exit 0 silently); they update with the plugin, never drift per-project.
- D2 **Decomposition scope: bash → scripts, phases stay.** All embedded bash (9b preflight/verdict, 9c, frontend detection, layer status) moves into plugin `scripts/pipeline/*.sh` invoked with arguments; phase prose remains in feature.md. Full skill extraction deferred.
- D3 **promptfoo: minimal skeleton** — `tests/promptfoo/` with a fixture project and 3-4 key behavioral scenarios; run manually before version bumps (documented in contributor CLAUDE.md), not wired to a CI service.

## What ships

1. **Plugin hooks** (D1):
   - `PostToolUse` (Bash matcher) — append a JSONL ledger row (`docs/superpowers/runs/tool-ledger.jsonl`, size-capped) for every Bash call during an active run: ground truth the verify phase and critic check claims against (the run-manifest stops being self-reported).
   - `Stop` — while a pipeline run is active in phases 9–10 and no fresh gate verdict exists → block session end ONCE (respect `stop_hook_active` to avoid loops), directing to finish or abandon the run.
   - `PreToolUse` (Bash matcher) — intercept `git merge` / `git push` / `gh pr create` during an active run: block (exit 2) when the current slug's visual/quant `verdict.json` says fail/partial-in-required, or the latest critic report has unresolved Critical without an override risk row.
   - `PreCompact` — snapshot `runs/current.json` + ledger tail before context destruction.
   - `UserPromptSubmit` — in pipeline projects, inject a compact digest: lessons index (filename + trigger), Serena memory names, active-run one-liner. Mechanical injection instead of trusting Phase-1 reads.
2. **Run-state + /resume (10th command):** `docs/superpowers/runs/current.json` {slug, f_id, branch, phase, approvals, updated} — a CACHE updated at phase boundaries; artifact files remain the truth. `/resume` derives the real position from artifact existence (spec → Approved line → plan → bd tasks → gate-2 report → evidence → merge), reconciles with the cache, and offers to continue from the derived phase. Stale cache never lies its way past a missing artifact.
3. **Machine verdicts:** senior-critic reports end with a fenced ```json block `{gate, critical, important, nice, status: pass|concerns|fail}` (last fence wins; concerns = Important-only); 9b and 9c additionally write `verdict.json` next to their summary.md — the files hooks and commands branch on.
4. **Bash → scripts** (D2): `scripts/pipeline/` — `detect-frontend.sh`, `visual-preflight.sh` (settings + dev server + URL extraction), `visual-verdict.sh`, `quant-verify.sh`, `layer-status.sh`, `resolve-plugin-dir.sh` (the sort -V snippet, defined once). feature.md phases call them; MCP tool calls remain prose. check.sh gains `bash -n` on every script + fixture runs of the two verdict scripts.
5. **Layer-status banner:** `layer-status.sh` probes the six layers; its one-liner prints at ground, lands in the final report, and is passed to the gate-2 critic.
6. **Playwright pinned:** `@playwright/mcp@0.0.79` (npm-verified 2026-08-19) in init.md registration + re-enable texts; pin recorded in contributor CLAUDE.md versioning policy.
7. **promptfoo skeleton** (D3): `tests/promptfoo/promptfooconfig.yaml` (claude-agent-sdk provider, local plugin, fixture working dir), `fixtures/miniproj/`, scenarios: (a) /feature halts at the playback gate with a digest and creates no bd tasks before approval; (b) /init confirms drafted lines before committing; (c) interview questions carry ➡️ recommendations; (d) 9b skip paths land in 9c. Run: `npx promptfoo eval -c tests/promptfoo/promptfooconfig.yaml` — manual, pre-bump.
