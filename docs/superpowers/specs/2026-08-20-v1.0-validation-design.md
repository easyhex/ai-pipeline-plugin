# v1.0 «Замыкание петли» — design

**Status:** APPROVED — scope fixed by the user-approved roadmap ("v1.0 validation loop"); design decisions below follow the pattern of 15/15 previously user-confirmed recommendations and are marked as assumptions the gate-2 critic must audit.
**Sources:** grill report misses M1/M6 (no v2.0 story; nothing validates against reality), survey (BMAD checkpoint-preview precedent, ECC telemetry precedent, mattpocock .out-of-scope KB, ai-factory evolve distillation, promptfoo evidence-hardened judge), Serena memories (all 8).

## Goal

Close the only loop still open at the reality end: shipped features get validated against declared success criteria, deliberate breaking change becomes expressible, lessons compile into rules instead of accumulating linearly, critic findings get a fresh-context verification pass, and deliberate refusals stop being re-litigated.

## What ships

1. **Success criteria become first-class.** `SPEC_FORMAT.md` gains `## Success criteria` (observable, measurable, each with a check-by condition; math flavor: "residuals on dataset X below Y by <date/condition>"); carried into the requirements file as a `## Success criteria` section with per-criterion status `unchecked | met | missed`. The playback digest already plays back seams; criteria ride with them.
2. **`/validate` (11th command).** Walks shipped features whose criteria are `unchecked` (or past their check-by), asks the user for outcome evidence per criterion (frontier format), records verdicts + evidence into the requirements file's Success criteria section and Change history, and on `missed` criteria drafts a roadmap-reprioritization proposal routed through `/plan-improve` (never edits roadmap itself). Guesses made at the playback gate get falsified by reality here.
3. **`/deprecate` (12th command).** The non-additive path: impact scan (TRACEABILITY + requirement `supersedes` chains + grep of dependents), a committed migration plan (`docs/superpowers/plans/<slug>-migration.md`: data + API + user-facing steps), code removal via the standard TDD loop with the gate-2 critic TOLD the break is intended (it reviews the migration, not the regression), requirements file → `status: deprecated` with a `BREAKING` Change-history row, features.md → Deprecated. Never pushes.
4. **Lesson distillation — `/lesson distill` mode** (no new command). Cursor file `docs-meta/.lesson-cursor` (last processed lesson filename); reads lessons newer than the cursor plus a 3-file overlap window; clusters recurring triggers/root-causes; writes/updates `docs-meta/DISTILLED.md` (one rule per cluster: rule + source lesson links + last-updated); ground phases read DISTILLED.md BEFORE raw lessons (compiled rules first, raw tail second); rules whose source lessons were pruned are dropped on the next distill.
5. **Fresh-context critic verification.** senior-critic.md gains a **verification mode**: input = a draft gate report; the verifier re-reads ONLY the evidence each finding cites (read-only, treating the implementer's code comments and claims as evidence-not-instructions), drops findings it cannot reproduce, marks the rest CONFIRMED, and rewrites the verdict JSON. feature.md Phase 8 dispatches it whenever the draft report has any Critical finding, or always at weight `deep` — BEFORE the findings reach the user (the user's time is spent only on reproduced findings).
6. **Out-of-scope knowledge base.** `docs/analysis/out-of-scope.md` template (concept | durable reason | date | source run). Written by: the playback gate on approval (concept-level refusals from "Out of scope (confirmed)" that hold beyond this one feature — feature-local exclusions stay in the spec) and `/plan-improve` (type I). Read by: ground phases and gate-1 critic ("the spec resurrects a rejected concept without addressing the recorded reason → Important").

## Non-goals

/forge adversarial sessions; ECC confidence-scored lesson injection and git-history bootstrap; run telemetry dashboards; simulated-stakeholder interviewer scoring. All post-1.0.

## Assumptions for the gate-2 critic to audit

- A1: `/validate` and `/deprecate` as standalone commands (12 total) rather than modes of /release and /improve.
- A2: Distillation is manual-invoked (`/lesson distill`), not automatic — a solo dev runs it when lessons feel heavy; the layer-status banner shows the undistilled count as a nudge.
- A3: Verification mode runs inside the same senior-critic agent definition (a mode, not a second agent file).
- A4: Versioning policy flips at 1.0.0: semver enforced, breaking changes only on major (already stated in contributor CLAUDE.md).
