# v0.5 «Требования» — design

**Status:** APPROVED — four open decisions answered by the user on 2026-08-18 (all recommended options; see Decisions).
**Sources:** grill report (requirements lens R1–R10, misses M1/M3/M4), market survey (cc-sdd EARS, StrictDoc MID/two-tier identity, OpenSpec update-vs-new rubric, BMAD counter-metrics + Binds/Prevents/Rule ADRs), v0.4 shipped mechanisms (playback gate, weight, provenance sections).

## Goal

Human-facing, versioned requirements artifacts: ФТТ/НТТ with enforceable grammar, living per-feature requirement files with per-requirement history, traceability from requirement to merge SHA, analog analysis, decision records, a risk register that survives overrides, and release machinery (/release + CHANGELOG) so versions exist that humans can name.

## Decisions (user-confirmed 2026-08-18)

- D1 **Requirements versioning:** living per-feature files (`docs/requirements/F-NNN-<slug>.md`) with per-requirement change history + `supersedes`/`superseded_by` headers. OpenSpec-style delta folders deferred.
- D2 **EARS:** mandatory for every FR/NFR acceptance criterion at weight `standard`/`deep` (critic flags violations); recommended at `light`.
- D3 **/release ships with MID:** every requirement carries an immutable `mid:` uuid; /release generates the "requirements changed since last release" CHANGELOG section by mid-diff between tags.
- D4 **Analogs:** template always installed; /init offers an optional web-search fill at bootstrap; later updates via /plan-improve. Ground + critic always read it.

## What ships

1. **`docs-meta/SPEC_FORMAT.md`** — the per-run spec schema: weight frontmatter; Goal; provenance sections (v0.4); `## Functional requirements` (FR-NN + EARS criterion); `## Non-functional requirements` (NFR-NN: metric, threshold WITH units, proving command, counter-metric per BMAD SM-C); Analogs considered; Test plan / seams; URLs to verify. Contains the EARS grammar (5 patterns + WHAT/HOW litmus) as its single home.
2. **`docs-meta/REQUIREMENTS_FORMAT.md`** — living requirement files: frontmatter (id, slug, status in_progress|shipped|deprecated, supersedes/superseded_by), FR/NFR blocks each with `mid:` uuid + status + EARS criterion + source provenance, `## Change history` table. Created at Phase 3.5 approval from the approved spec; amended by /improve (update-vs-new rubric: same intent? >50% overlap? original "done" without this? coherent story? → amend in place vs successor file).
3. **`docs-meta/ADR_FORMAT.md`** + `docs/decisions/` — Context/Decision/Consequences + Binds (F/FR/NFR ids) / Prevents / Rule; three-gate test (hard to reverse ∧ surprising without context ∧ real trade-off). Critic marks decision-class memory suggestions with `[decision]`; the orchestrator then ALSO writes a committed ADR (no duplicate write logic across commands).
4. **`docs/risks.md`** — 4th Master Plan file. Every critic-gate `override` auto-appends a row (R-NNN, date, finding, reason, review-by condition, link); ground reads it; critic receives it at both gates and re-flags open risks matching current work; /plan-improve retires rows.
5. **`docs/glossary.md`** — term | definition | units | avoid-synonyms; seeded by /init interview; read in every ground.
6. **`docs/analysis/analogs.md`** — analog | what it does | what to copy | what to avoid | sources | date checked; NOT-doing roadmap entries cite it; critic checks "spec reinvents what an analog proved wrong".
7. **`docs/TRACEABILITY.md`** — one row per run appended at Phase 11: F-ID | slug | spec | plan | gate-1 | gate-2 | evidence | merge SHA | date. F-ID minting rule: next unused F-NNN across all sections of features.md (fixes the `[F-XXX]` placeholder).
8. **`/release` (9th command)** — next semver from shipped-since-last-tag (+ user-confirmed breaking question), human-register CHANGELOG.md from spec summaries (not commit messages), mid-based requirements-diff section, `shipped in vX.Y.Z` stamps in features.md, local tag, NO push.
9. **Versioned Master Plan docs** — `doc_version` + `last_changed` frontmatter + `## Change history` table on architecture/features/roadmap/risks templates; /plan-improve bumps + appends on every apply; /feature Phase 11 appends the features.md row.

## Non-goals
