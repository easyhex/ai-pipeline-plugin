# v0.6 «Математика» — design

**Status:** APPROVED — four open decisions answered by the user on 2026-08-18 (all recommended; see Decisions).
**Sources:** grill report (heavy-math lens M1–M8), market survey (StrictDoc verification-method enum + code markers, ECC pass^k, Spec Kit anti-overclaim, BMAD claims-check + verification-gap, promptfoo verifier-sabotage, cc-sdd contracts + feature-flag RED, completeness-critic blind spots: mutation testing + property tooling), Serena memories (runstate-substitutes-v04, inheritance-delta-checklist, command-bash-block-state).

## Goal

Point the pipeline's verification machinery at the author's actual domain: numerical correctness becomes declarable (oracles, tolerances with units, invariants), measurable (quant-verify gate with durable evidence and honest acceptance semantics), and reviewable (a critic that knows numerical failure modes and distrusts both the spec's claims and the tests themselves).

## Decisions (user-confirmed 2026-08-18)

- D1 **Mutation testing:** `pipeline.quant_verify.mutation: off | advisory | required`, default `advisory` — survivors become Important critic findings, never a block by default.
- D2 **Code traceability:** `@relation(F-NNN/FR-NN)` docstring markers + coverage check in v0.6; hash-stamped links too, but a `suspect` link (code changed since requirement verification) is an Important finding, not a gate block.
- D3 **Verification-method enum** `Test | Analysis | Inspection | Review` per requirement: mandatory for numerics-class projects (method-specific evidence obligations), optional elsewhere.
- D4 **Phase 9c default mode:** `required` for compute project classes (a failing NFR proving command stops the pipeline); an NFR with no proving command is an Important finding, not a block.

## What ships

1. **Project class** — /init interview asks it (numerical-library / simulation / data-pipeline / service / ui-app / cli); written to `.claude/settings.json` → `pipeline.project_class`; sets defaults: `visual_verify.mode` (skip for compute classes, required for ui-app), `quant_verify.mode` (required for compute classes, skip for ui/service unless NFRs declare commands), coverage-tree variant recommendation.
2. **`docs/model.md`** (compute classes only) — mathematical model, assumptions, invariants, units/symbols (links glossary), accuracy targets naming their oracles, known failure regimes. Owned by /plan-improve; read in ground; versioned like Master Plan docs.
3. **`docs-meta/NUMERICS_TESTING.md`** — the oracle taxonomy (analytic special case / manufactured solution / property-metamorphic / reference implementation / convergence order) with a compact example each; the tolerance-justification rule; "tolerance chosen to make the test pass" as a NAMED stop condition; the feature-flag honest-RED protocol; property obligation: every numerical FR names ≥1 property/metamorphic relation.
4. **Phase 9c quant-verify gate** (canonical ONLY in feature.md, per the rule-8 pattern): settings block `pipeline.quant_verify` {mode, budgets, property_test_command, benchmark_command, tolerance_report_command, mutation}; iterates the requirements file's NFR proving commands + declared oracles; evidence to `docs/superpowers/quant-evidence/<SLUG>/` — `summary.md` verdict + `run-manifest.md` (commit SHA, seeds, platform, dependency versions, input-data hashes); **pass^k** semantics (deterministic oracles: all manifest seeds must pass; pass@k reserved for stochastic, both reported); **anti-overclaim**: verdict `verified` only if the manifest shows every declared oracle executed, else `partial` with the unexecuted list; mutation sub-step per D1; @relation coverage + hash-suspect checks per D2. /improve and /fix get explicit 9c deltas (inheritance-delta-checklist).
5. **Numeric critic** — senior-critic.md gains "Numerical correctness" duties at both gates with typed severities: exact float equality in a test → Critical; new solver/algorithm without a declared oracle → Critical; tolerance without justification → Important; stochastic test without pinned seed → Important; NaN/Inf/domain-boundary handling at public API → Important; unjustified accumulation-order change → Important; "tolerance fraud" joins the fake-tests list. Plus: **claims-check quarantine** (stage 1: trace the diff's numerical paths WITHOUT the spec; stage 2: compare the spec's claims to the trace — "the spec is testimony, not evidence"); **verification-gap lens** ("if this behavior broke, which check fails?"); **verifier-sabotage check** (any diff to test/tolerance/seed files is compared against the task's stated intent).
6. **Requirements schema extensions** (REQUIREMENTS_FORMAT + SPEC_FORMAT): `verify: {method: Test|Analysis|Inspection|Review, oracle: <taxonomy type>, evidence: <path>}` per requirement (mandatory for numerics classes; Test → oracle + test id, Analysis → committed derivation doc, Inspection/Review → report link); `@relation` marker convention + `code: {path, symbol, sha256, verified_at}` link entries; `## Mathematical approach` and `## Interface contracts` (Pre/Post/Invariants per public numerical interface) as mandatory SPEC_FORMAT sections for compute classes — gate-1 flags a numeric spec without them as Critical.

## Non-goals

Hook-level enforcement of 9c verdicts (v0.7). Stochastic-arithmetic lanes (Verificarlo/Herbie) — documented as options in NUMERICS_TESTING, not wired as gate machinery. /validate outcome loop (v1.0).
