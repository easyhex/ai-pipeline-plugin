# v0.4 «Обкатка» — design draft

**Status:** APPROVED — all four open questions answered by the user on 2026-08-18 (recommended options confirmed; see "Decisions" below).
**Sources:** grill report (elicitation lens, findings E1–E9), market survey (LLMREI cluster, Spec Kit, cc-sdd, BMAD, OpenSpec, StrictDoc), user goal statement.

## Goal

Make elicitation the pipeline's strongest phase instead of its suppressed one: the pipeline interviews until shared understanding, plays the spec back for explicit sign-off, and only then runs autonomously. Autonomy belongs to phases 4–11; phase 2 belongs to the user.

## Non-goals (v0.4)

- Full SPEC_FORMAT with FR/NFR-NNN + EARS grammar (v0.5; v0.4 ships only the three provenance sections).
- Requirements delta-versioning, traceability, /release (v0.5).
- Numerics gates and project-class routing (v0.6).
- Hook-level enforcement of the sign-off (v0.7; v0.4 sign-off is prompt-level + approvals ledger field).

## What ships

### 1. `assets/templates/ELICITATION.md` — the elicitation primitive (single source of truth)

Copied to `docs-meta/` by /init. Referenced (never duplicated) by /feature Phase 2, /plan-improve Phase 3, /init interview, /questionnaire. Contents:

- **Frontier rounds:** the design tree; a round = every question whose prerequisites are settled; numbered `❓ N` questions, each with `➡️ Recommended: <option> — <reason>`; user answers by number ("1 да, 2 второй вариант").
- **Facts vs decisions:** facts the agent looks up itself (files, docs, web); decisions go to the user and the agent WAITS. No question caps; the bound is by kind, not count.
- **Question hygiene (hard rules):** the 14-mistake lint (no generic questions, no jargon, no leading questions embedding the answer, no compound questions, no questions answerable from the repo, …). Before printing a question, silently self-check; rewrite on any hit.
- **Micro-playback:** a slot becomes Confirmed only after the user affirms a one-sentence paraphrase. Hedged answer → slot reopens.
- **Surprise-chasing:** an entity outside the coverage tree → log to `Surprises` + at least one follow-up.
- **Forced NFR round:** the final pre-playback round iterates non-functional dimensions explicitly (tolerances, units, performance envelopes, determinism) — measured LLM blind spot (IRE_STY < 0.01), never left to chance.
- **Coverage state:** `docs/superpowers/elicitation/<SLUG>-state.md` — Aspect → Dimension → Slot tree with Unexplored / Confirmed / Rejected; next question targets uncovered slots.
- **Typed clarification debt:** unresolved items are written into the artifact as `[NEEDS CLARIFICATION: …]` (cap 3 per artifact) or `TBC:` (user must confirm) / `TBD:` (we must decide); empty fields are forbidden; gates count open markers.

### 2. /feature Phase 2 — explicit contract + no more silence

- Delete "Otherwise proceed silently". Replace with the facts-vs-decisions rule.
- State which superpowers:brainstorming gates are IN FORCE inside the pipeline: the spec-review gate survives; the per-section design approvals are superseded by the playback gate (one consolidated stop instead of many).
- Rewrite the announcement: "Я интервьюирую до общего понимания, проигрываю спеку на подпись, затем еду автономно до финиша."

### 3. New Phase 3.5 — playback gate (the single blocking interaction)

Between critic gate-1 and Phase 4 (plan). Present the decision digest:
(a) verbatim request; (b) decisions made (from Confirmed slots); (c) assumptions the machine made unconfirmed; (d) out of scope; (e) seams — the invariants/tolerances/tests that will prove it. Critic `assumption`-typed findings of ANY severity are surfaced here. Open TBC count printed. Requires explicit yes; the original request is declared non-authorizing for the build (OpenSpec's planning-boundary clause). Recorded in run-state as `approvals.spec: true`.

### 4. Spec provenance sections (minimal, ahead of v0.5 SPEC_FORMAT)

Every spec gains three mandatory sections: `## User decisions (verbatim)`, `## Assumptions (machine, unconfirmed)`, `## Out of scope (confirmed)`. Gate-1 critic checks: material requirement outside User decisions must appear in Assumptions.

### 5. /init interview + line-by-line confirm

Phase 2 quiz replaced by a short frontier interview per ELICITATION.md (stakes probe first — see Q2). Phase 4's machine-drafted features/roadmap/NOT-doing are presented line-by-line for confirm/edit/delete BEFORE the first commit; anything unconfirmed carries `(proposed — unconfirmed)` until /plan-improve clears it.

### 6. /questionnaire — new command (see Q3)

Two-exchange interview about the send (who holds the knowledge; what must come back), then generates `docs/requirements/questionnaire-<slug>.md`: themed most-important-first sections, one idea per question, answer stubs, explicit "I don't know is useful", closing catch-all. Return path: ground phase of the next /feature reads answered questionnaires; answers land in User decisions with provenance.

### 7. Ceremony weight (anti-9×-overhead guard)

The stakes probe sets `weight: light | standard | deep`, recorded in run-state and read by later phases (which spec sections are required, critic pass count, playback digest length). Defaults: light for small asks, standard otherwise, deep on request.

### 8. Gate logic fixes riding along

- Important-only critic default defined: present findings, ask continue/address (no silent pass-through).
- The unimplementable "1 message exchange" timeout deleted: gate decisions are synchronous questions.

## Assumption ledger (confirm or correct)

- A1: Playback gate is THE only blocking stop of a normal run; everything after sign-off stays autonomous.
- A2: Coverage-tree templates ship in the plugin (generic + numerics variant); chosen by one interview question, not by project-class detection (that arrives in v0.6).
- A3: ELICITATION.md is user-visible documentation (docs-meta/), not hidden prompt matter — users may edit it per-project.
- A4: check.sh grows contract tests: ELICITATION.md referenced (not duplicated) by the three commands; "proceed silently" absent; playback section present; provenance sections in the spec template.

## Decisions (user-confirmed 2026-08-18)

- D1 **Формат раундов:** фронтир-раунды (весь фронт зараз, нумерация ❓1..N, ответ номерами) с опт-аутом «When grilling, ask one question at a time» в пользовательском CLAUDE.md.
- D2 **Playback при weight=light:** сокращённый дайджест (3 строки: что делаю / допущения / что докажет), но явное «да» обязательно при любом весе. Полный дайджест на standard/deep.
- D3 **/questionnaire:** входит в v0.4.
- D4 **Язык артефактов:** проза — на языке беседы; все ID (FR-001), статусы, имена файлов и greppable-маркеры ([NEEDS CLARIFICATION], TBC/TBD) — английские, никогда не локализуются (паттерн ai-factory).
